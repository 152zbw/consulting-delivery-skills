# 咨询交付 Skills

四个可独立安装的中文咨询技能，适用于咨询公司售前及交付准备。参考公开咨询实践，自主编写，非美世、埃森哲、麦肯锡官方产品。

|Skill|用途|
|---|---|
|`consulting-proposal`|方案建议书：客户问题、证据、方法、工作包与价值论证|
|`consulting-sow`|工作说明书：范围、成果、验收、责任与变更|
|`consulting-bid`|咨询标书：条款解析、材料台账、响应及缺项检查|
|`consulting-training-outline`|培训大纲：岗位任务、目标、实践、评价与应用|

## 安装及调用

把 `skills/` 下需要的独立文件夹（包含 SKILL.md、references 和 agents）复制到 `~/.codex/skills/`，按客户端要求重新加载技能。其他支持 SKILL.md 的工具按其安装方式导入。AI 能读取 GitHub 不代表技能已经安装，私有仓库还需要访问授权。

例如：

```text
请使用 $consulting-proposal。公司模板：……；本次确认需求：……；服务模块：……；已确认预算与工期：……。先做一个模块，输出可编辑初稿与证据/缺口清单。

请使用 $consulting-sow。以已确认方案、报价和合同模板为准，写 SOW，重点检查交付验收与范围边界。

请使用 $consulting-bid。根据招标文件及正式答疑，先形成材料索引、逐条响应矩阵和否决项缺口表，再写技术响应。

请使用 $consulting-training-outline。按公司模板为【角色】设计【时长】的【主题】培训，提供目标—活动—评价映射及准确日程。
```

## 模板与公司知识

仓库只放通用 skill、公开来源及虚构验证案例。已基于多种历史样例补充模板类型与分流规则。客户原件及本地路径未进入公开仓库；这些规则不等于已打包公司原生模板，也不代表通过真实项目生成验收。调用时仍需提供所选模板或内部资料位置。

请在内部位置维护：公司模板（版本/负责人/适用范围）、服务模块（方法/输入/成果/边界）、案例及资质（授权/主体/有效性）、报价与排期（批准版本）。调用时提供路径或经授权的连接。不要将客户、报价、履历、证书原件或密码提交到本公开仓库；读取权限不构成对外发布授权。

缺失信息用待确认标记，不自行补商业承诺。文件制作取决于调用环境的文档工具；本仓库不捆绑 Office 渲染器。每次交付均有客户质询及修订记录，仍需业务负责人核对事实、范围和商务条件。

## 质量验证

`tests/scenarios.md` 是行为验收场景与判定标准，覆盖矛盾需求、缺材料及时间约束。`VALIDATION.md` 记录实际执行检查与限制；结构验证不等于交付质量保证。获得真实模板后应以历史项目脱敏回放并记录修订，再作为团队标准版本推广。

## 四个 skill 放在同一仓库，如何区分？

仓库是安装来源，每个 `skills/<name>/SKILL.md` 是独立入口。安装时保留四个文件夹，不把四份 SKILL.md 合并。只需某一个也可只安装该目录。

|要做什么|明确调用|在技能内指定的选项|
|---|---|---|
|建议书|`$consulting-proposal`|简版/详细阅读版/PPT汇报版，输出 Word 或 PPT|
|工作说明书|`$consulting-sow`|简版协议/模块式范围/复杂专项，及所选模板|
|投标文件|`$consulting-bid`|技术标/商务标/两册/讲解PPT|
|课程大纲|`$consulting-training-outline`|客户确认版/讲师实施版，课时与对象|

例如：`请用 $consulting-proposal，参考附件中的详细方案结构，输出 Word；另一份 PPT 只作为表达参考，不沿用其业务范围。`

例如：`请用 $consulting-sow，采用附件的模块式结构，以本次批准范围为准；其他 SOW 仅供措辞参考。`

也支持一次要求配套建议书与 SOW：显式调用两个 skill，分别输出，并核对目标、范围、成果、周期、费用及排除项。自然语言可自动匹配，显式技能名最清楚；只有复制文件到 GitHub 并不等于所有 AI 自动获得调用能力。

## 交付增强版的实际执行流程

输入基线与模板选择 → 章节标准与方法选择 → 初稿 → 多角色质询 → 修订与复核 → 原生文件制作 → 最终页面检查 → 当前版本业务确认 → 客户交付包。已确认输入不重复问；缺关键事实或商务条件则保留工作草稿，不制造“看起来能交付”的假定稿。

每个独立skill新增：章节标准、教学虚构示例与反例、输入与方法选择、多角色审查协议、客户交付关口、manifest示例及辅助检查脚本。脚本只检查记录和基本文件结构，不验证事实、合同适用和视觉品质。客户正文与内部审查记录分开。

“直接交付”是通过具体检查后达到的状态，不是仅凭安装skill即可保证的结果；文件质量还取决于本次资料与执行环境的原生文件生成和渲染能力。
