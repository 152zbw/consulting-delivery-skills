# 多角色质询与专业审查

这是可追溯审查流程，不是要求输出隐藏推理。最终只记录发现、依据、修改和复核结论。单个AI可依次切换角色；没有独立审稿人时明确为同一AI自审，不声称独立评审。若执行环境提供且当前任务授权独立审查，可将完成稿与最小证据交给独立审阅者，仍由主执行者核对结论。

## 角色与审查任务

|角色|最关心的问题|必须检查的证据|
|---|---|---|
|客户决策者|为什么做、为什么这样做、是否值得投入|关键结论、替代方案、价值链、投入前提|
|客户业务负责人|是否理解业务、谁执行、能否使用|工作场景、活动、资源、依赖、成果样态|
|采购/合同管理者|买到什么、边界在哪、如何验收|范围、排除、价格、义务、变更和批准来源|
|咨询交付负责人|团队能做吗、工期够吗、如何控制质量|工作分解、人日、排期、接口、客户输入与风险|
|证据核验者|事实是真的吗、出处支持这句话吗|来源、统计口径、当前有效性、主体及授权|
|编辑与文件审阅者|文档是否完整、准确、可读可编辑|目录编号、跨文件一致、渲染、元数据与附件|

培训另加入学员和讲师视角，标书加入评委视角；按业务取舍角色，不能把一次自审冒充多位真人批准。

## 操作步骤

1. 固定当前版本、需求基线与来源清单，先检查致命缺口，再检查内容。
2. 各角色围绕本次正文提出具体质疑：必须引用章节、页码或段落ID，说明为什么现有证据不足。问题数量取决于实际发现，不凑数。
3. 判定严重度：P0为可能造成不实承诺、资格不满足、金额/主体错误或敏感信息误披露；P1为核心需求漏项、成果不可验收、论证断裂、排期资源不可行或文件不可用；P2为表达、局部结构及易读性问题。优先级是内部定义，不冒称行业认证。
4. 可由现有证据解决的直接修改；缺输入的列责任人/所需证据/影响，不编答案。不可把P0/P1通过降低标记或删除审查记录“解决”。
5. 修订后检查修改位置及受影响的其他章节/文件。发现新矛盾继续处理；最多两轮完整审查后仍未关闭的严重项，降为待补齐或待业务复核，不标定稿。
6. 用当前版本重开文件及复核关键结论，记录关闭依据。不能将“已修改”直接等同“已关闭”。

## 审查记录格式

|ID|版本/位置|角色追问|严重度与影响|证据/来源ID|修改动作|复核证据|状态|
|---|---|---|---|---|---|---|---|

状态：开放、已修改待复核、关闭、不适用（附理由）。核心表述变化应保留简短修订摘要。P2也需修复或明确保留原因。给客户的正文不附内部质询过程，除非用户明确需要；内部记录与交付文件分开保存。

## 审查项目状态（区别于问题的关闭状态）

每项检查记录通过、不通过、未评估或不适用。未评估必须写缺失证据及影响，不适用必须有理由。核心范围、资格、事实或商务检查未评估时，不可把总状态标为客户定稿。审阅稿的版本改变会使受影响检查失效，需针对性复核。
