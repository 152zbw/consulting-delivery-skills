# 示例与反例（均为教学虚构，不是公司业绩）

输入：虚构设备企业已确认报价到合同周期长；访谈提示技术澄清反复，但缺少系统记录。拟做流程诊断和一个试点，不含系统开发；商务未批准。

差：贵司缺乏销售能力，通过领先模型赋能，三个月提升收入30%。
问题：把假设当根因；未说明活动与成果；收益、时间和能力判断没有证据。

较好：已确认问题是报价到合同的推进周期偏长。技术澄清反复可能是原因之一，尚需以样本商机记录验证。建议先复盘成功、停滞及丢单场景，定位等待、返工和决策缺口，再设计关键评审与交接规则，并在双方确认的一个场景试用。交付包含诊断结论、改进流程和试点反馈；不包含系统开发。改善效果以双方确认基线和观察期评估，当前不作收入承诺。商务条件另依据批准报价填入。

这段只是工作草稿：样本、周期、角色和批准商务未齐全，不能标为客户定稿。改写的质量在于论证与边界，而非把待确认藏掉。

## 客户追问及修订示例

追问：“你怎么确定是技术澄清造成周期长？”
修订：将确定性原因改为待验证假设，新增对商机阶段记录及返工原因的核对，保留其他解释，如采购等待和资源排队。
追问：“流程图交给谁用？”
修订：明确评审负责人、使用场景、试点记录和维护责任，而非再加一页方法论。
